THE METAPHOR

Four rules, and the whole repo makes sense

Buildings are files

Height is lines of code. A 3,000‑line module is a tower; a config stub is a shed. Watch a file grow floor by floor as it’s edited.

Districts are folders

A squarified treemap zones the ground by directory, and the gaps it leaves become the street grid. Structure before detail.

Type picks the form

Twelve massing types. Source code builds offices and towers, docs build churches and civic halls, config builds depots and utility yards.

Every commit, replayed

One frame per commit — not a sampled approximation. Scrub the full history and see exactly when each building appeared.

HOW IT WORKS

Paste a URL. Get a city.

01

Paste any public repo

Drop in a GitHub URL. No signup, no install, no access token.

02

We replay the git log

One pass of git log --numstat reconstructs every file’s line count at every commit — without ever checking one out.

03

The city rises

Buildings break ground one at a time, in commit order, until the repo stands at HEAD.

UNDER THE HOOD

Built to survive real repositories

One draw call, any size

Every building of a given shape lives in a single InstancedMesh. A 10,000‑file repo costs the same handful of draw calls as a 10‑file one.

Streamed git parsing

The log is parsed line by line as it arrives, so a repo with hundreds of megabytes of history never lands in memory at once.

Real materials

Ground‑truth ambient occlusion, an environment probe for glazing, and procedural facades with window reveals — so buildings read as solid, not as boxes.
